# MultiPaper 26.2 移植实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 本计划由主执行者按阶段推进;每个移植任务遵循统一冲突处理循环。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 MultiPaper 水平扩展(多服务器共享世界)从 Purpur 1.20.1 完整移植到 Purpur 26.2(paperweight 2.0.0-beta.21 / Gradle 9.4.1 / Java 25),全量 150 个 server 补丁 + 9 个 api 补丁功能对等。

**Architecture:** MultiPaper 26.2 = Purpur 26.2 (ver/26.2 @ 8762b2f) + 迁移后的 MultiPaper 补丁集。补丁布局从旧平铺 `patches/*.patch` 迁移到 paperweight 2.x 的 `multipaper-server/{paper-patches,minecraft-patches}/features/` 与 `multipaper-api/paper-patches/features/`。架构模型不变:Master 协调 chunk 所有权 + P2P 同步 + 玩家路由。

**Tech Stack:** Kotlin DSL Gradle 9.4.1, paperweight 2.0.0-beta.21, Java 25 (GraalVM 25.1.3 本机), git 2.45, Windows 11。

## Global Constraints

- 目标上游: Purpur `ver/26.2` @ commit `8762b2f`(已浅克隆至 `E:/var/mp-ref/purpur-26.2` 作参考)
- 产物: `group = puregero.multipaper`, `version = 26.2-R0.1-SNAPSHOT`, `mcVersion = 26.2`
- 补丁布局(paperweight 2.x): server→`multipaper-server/paper-patches/features/`(io.papermc 代码)+ `multipaper-server/minecraft-patches/features/`(net.minecraft 代码);api→`multipaper-api/paper-patches/features/`;removed 反向补丁同样分类迁移
- 保留模块零改动: `MultiPaper-MasterMessagingProtocol`、`MultiPaper-Master`(除非编译期必须适配)
- 行为对等优先于 diff 保真;特性失效必须文档记录,禁止静默砍功能
- 工作分支: 本地 `ver/26.2`,main 保持不动
- RAM 预算: 16GB 总内存,构建时空闲须 ≥5GB;Gradle daemon `-Xmx4G -XX:MaxMetaspaceSize=1G`, `org.gradle.workers.max=2`
- 网络: raw.githubusercontent.com 不可达;一律 git 协议 + repo.papermc.io / services.gradle.org(已实测可用)
- 每完成一个补丁组: `rebuildPatches` 落盘 → 提交 → 记录旧补丁→新补丁文件映射(全量对等清单)

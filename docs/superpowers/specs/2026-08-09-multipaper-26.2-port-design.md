# MultiPaper 26.2 移植设计

- 日期: 2026-08-09
- 状态: 已确认(用户于 2026-08-09 批准)
- 范围: MultiPaper 主分支(水平扩展)完整移植到 Minecraft 26.2,全量功能对等

## 1. 目标

将 MultiPaper 主分支(多服务器共享同一世界的水平扩展架构)从 Purpur 1.20.1
完整移植到 Purpur 26.2。验收标准:**全部 150 个 server 补丁 + 9 个 api 补丁
等价移植**,一次到位,不砍功能。

## 2. 背景事实

- 当前仓库: MultiPaper main = Purpur 1.20.1 fork,paperweight 1.5.7-SNAPSHOT,
  Gradle 旧 wrapper,Java 17,平铺补丁布局 `patches/{server,api,removed}/*.patch`
  (150 + 9 + ~20 removed,共约 2.5 万行)。
- 目标上游: Purpur `ver/26.2` @ `8762b2f`,paperweight `2.0.0-beta.21`,
  Gradle 9.4.1,Java 25 toolchain,新补丁布局:
  - `purpur-server/paper-patches/features/*.patch`(io.papermc 代码)
  - `purpur-server/paper-patches/files/src/...`(整文件覆盖)
  - `purpur-server/minecraft-patches/features/*.patch`(net.minecraft 代码)
  - `purpur-api/paper-patches/*`(API)
- MultiPaper 官方无 26.x 分支;`dev/3.0`(1.20.6)与 ShreddedPaper(ver/26.2)
  均为垂直扩展(单服务器多线程)架构,与水平扩展不同,无可复用补丁。
- 本机: Windows 11,Java 25 (GraalVM 25.1.3),git 2.45,16GB RAM,E: 盘 64GB 空闲。

## 3. 架构决策

- **D1 架构模型不变**: Master 协调 chunk 所有权、服务器间 P2P chunk 同步、
  玩家路由与包转发。仅内核心实现随 26.2 演进。
- **D2 补丁布局**: 迁移到 paperweight 2.x 结构:
  - `multipaper-server/paper-patches/features/` — 作用于 Paper/Purpur 服务端代码
  - `multipaper-server/minecraft-patches/features/` — 作用于 Mojang-mapped NMS 代码
  - `multipaper-api/paper-patches/features/` — API 补丁
  - 混合补丁(同一补丁同时含 NMS 与 Paper hunk)拆分为多个补丁文件,按 hunk 目标归类。
- **D3 removed 补丁**: `patches/removed/*` 保留为反向补丁,按同样分类规则迁移。
- **D4 产物标识**: `group = puregero.multipaper`、`version = 26.2-R0.1-SNAPSHOT`、
  `mcVersion = 26.2` 不变式保持。
- **D5 独立模块**: `MultiPaper-MasterMessagingProtocol`(纯协议,无 MC 依赖)与
  `MultiPaper-Master` 原则上零改动;若编译期受 API 变化影响,做最小适配。
- **D6 移植保真度**: 优先行为对等,不追求 diff 保真;旧补丁上下文无法套用时,
  在 26.2 内核心上按语义重写。
- **D7 特性失效处理**: 若 26.2 上游机制使某 1.20.1 特性失去对应钩子,做语义
  等价替代并写入文档;禁止静默砍功能。
- **D8 验证方式**: 本地 Master + 2 节点冒烟;玩家路径若无 26.2 兼容 bot 客户端,
  以代码审查 + 人工验收清单覆盖。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| RAM 紧张(16GB 总,空闲约 3-4GB) | 构建前清理占用进程、`-Xmx4G`、限制并行 worker |
| 26.x 内核心大改(chunk 存储/线程模型/registry)导致核心补丁上下文断裂 | 编译错误 + 运行行为驱动重写;核心补丁由主执行者处理 |
| raw.githubusercontent.com 不可达(已实测) | 全程 git 协议 + 官方 maven;Gradle wrapper 走 services.gradle.org |
| paperweight 2.x DSL 与旧版差异 | 阶段 0 先研究 paperweight 2.x 源码/文档再落 build 文件 |
| 玩家同步路径无自动化验证 | 代码审查 + 提供人工验收清单 |
